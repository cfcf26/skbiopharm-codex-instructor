# 공유 전 Self-check

현재 Codex에서 연 폴더를 공유하거나 GitHub에 올리기 전에 점검한다.

## 지킬 규칙

- 이 Skill은 **점검만 한다.** 파일을 고치거나 지우지 않고, Commit이나 Push도 하지 않는다.
- 고칠 내용이 있으면 결과 표 아래에 목록으로 제안하고, 사용자가 요청할 때만 고친다.
- 판단하기 어려운 항목은 추측하지 말고 "확인 필요"로 표시한 뒤 사용자에게 묻는다.

## 점검 순서

### 1. 점검 범위 확인

- 현재 폴더 경로와 Git으로 관리되는 폴더인지 확인한다.
- Git 폴더라면 `git status`로 아직 Commit하지 않은 파일과, 올라갈 파일 목록을 확인한다.
- `.git` 폴더 안의 파일은 점검 대상에서 뺀다.

### 2. 민감정보·Secret

폴더 안의 파일 내용에서 아래 항목을 찾는다. 엑셀 파일은 시트 내용까지 읽는다.

- 사람 이름으로 보이는 값, 이메일 주소, 전화번호(예: 010-1234-5678), 주민등록번호 형태의 숫자
- API 키·토큰·비밀번호로 보이는 값(예: `password=`, `token`, `sk-`, `ghp_`로 시작하는 긴 문자열)
- `.env`, 인증서·키 파일(`.pem`, `.key`)
- 실제 사내 데이터로 보이는 값. 실습 데이터는 모두 가상 값이므로, "가상 데이터" 표시가 없는 데이터 파일은 사용자에게 출처를 묻는다.

Git 폴더라면 지금 파일뿐 아니라 이전 Commit에 남아 있는지도 확인한다. 파일에서 지웠어도 이력에 남아 있으면 그대로 공유된다.

- 텍스트 파일(HTML, Markdown, CSV, 코드)은 최근 20개 Commit까지 `git log -p`로 확인한다. 이력이 더 길면 확인한 범위를 결과에 적는다.
- 엑셀 같은 바이너리 파일은 `git log -p`에 내용이 나오지 않는다. `git log --name-only`로 이전 버전이 있는 엑셀 파일을 찾고, 있으면 "확인 필요"로 표시한 뒤 이전 버전도 열어 볼지 사용자에게 묻는다.
- 읽지 못한 파일이나 출력이 잘려 끝까지 보지 못한 내용이 있으면 "통과"로 처리하지 말고 "확인 필요"로 표시한다.

### 3. README

- `README.md`가 있는지 확인한다.
- 무엇을 하는 결과물인지, 어떻게 여는지(어떤 파일을 브라우저로 열면 되는지), 데이터가 가상인지가 적혀 있는지 확인한다.
- README에 적힌 파일이 실제로 폴더에 있는지 확인한다. 없으면 "공유 보류" 사유가 된다.

### 4. 변경 사항

- 마지막 Push 이후 바뀐 파일 목록을 보여준다. 처음 올리는 폴더라면 전체 파일 목록을 보여준다.
- 대시보드 같은 HTML 결과물은 그 파일이 참조하는 데이터·이미지 파일이 폴더에 있는지 확인한다.

### 5. 올라갈 레포와 공개 범위

- `git remote -v`로 올라갈 레포 주소를 보여준다.
- 공개 범위(Private·Internal)는 Codex가 확인할 수 없으므로, 사용자에게 브라우저에서 레포를 열어 공개 범위를 확인하도록 안내한다.
- 지금 Branch 이름을 보여주고, `main`에 바로 올리려는 상황이면 알려 준다.

### 6. 복구 지점

- 최근 Commit이 있는지, Commit하지 않은 변경이 남아 있는지 확인한다.
- 문제가 생겼을 때 돌아갈 Commit이 있는지 알려 준다.

- 확인 필요 항목이 있으면 사용자가 답한 뒤 다시 판정한다.
