# Git 작업 도우미

Git과 GitHub를 처음 쓰는 사람이 지금 무슨 일이 일어나는지 이해하면서 작업하도록 돕는다.

## 지킬 규칙

- **한 번에 한 단계만 진행한다.** 각 단계가 끝나면 결과를 보고하고, 다음 단계는 사용자가 확인한 뒤에 진행한다.
- 명령을 실행하기 전에 무엇을 하려는지, 그 결과가 내 PC에만 남는지 GitHub에도 올라가는지 한 줄로 먼저 말한다.
- 아래 작업은 사용자가 그 작업을 직접 요청했을 때만 한다.
  - Push (GitHub에 올리기)
  - Branch 삭제
  - 되돌리기 중 이력을 지우는 작업(`git reset --hard`), 강제 Push(`--force`)
- Git 용어는 처음 나올 때 괄호로 쉬운 설명을 붙인다. 예: Commit(저장 지점), Push(GitHub에 올리기)

## 1. 지금 상태 설명

사용자가 상태를 물으면 아래 내용을 확인해 쉬운 말로 알려 준다.

- 지금 연 폴더 경로와 Git으로 관리되는 폴더인지
- 지금 Branch 이름(`main`인지, 별도 작업 공간인지)
- 연결된 GitHub 레포 주소(`git remote -v`)
- 아직 Commit하지 않은 변경 파일
- Commit했지만 아직 GitHub에 올리지 않은 저장 지점 수
- GitHub에 새로 올라왔지만 아직 받지 않은 변경이 있는지(`git fetch` 후 확인)

마지막에 "다음에 할 수 있는 일"을 한두 개 제안한다. 예: "바뀐 파일 2개를 저장 지점으로 남길 수 있습니다."

## 2. 저장 지점 이름 붙이기 (Commit)

1. `git status`로 바뀐 파일, 새로 생긴 파일(아직 Git이 관리하지 않는 파일), 이미 Commit 대상에 올라간 파일을 나눠서 보여준다.
2. `git diff`(아직 올리지 않은 변경)와 `git diff --cached`(이미 Commit 대상에 올라간 변경)로 내용을 확인하고 짧게 요약한다. 새로 생긴 파일은 파일 이름과 무엇을 담은 파일인지 적는다.
3. 이번 저장 지점에 넣을 파일 목록과, 무엇을 바꿨는지 드러나는 한글 Commit 이름을 제안한다. 예: "예산 대시보드에 부서 필터 추가"
4. 사용자가 파일 목록과 이름을 확인하면, 확인받은 파일만 `git add <파일 이름>`으로 지정해 Commit한다. `git add .`이나 `git add -A`로 한꺼번에 넣지 않는다.
5. Commit 이력의 최근 3개를 보여주고, 이 저장 지점은 아직 내 PC에만 있다고 알려 준다.

## 3. 받아 오기 (Pull)

1. Commit하지 않은 변경이 있는지 먼저 확인한다. 있으면 받아 오기 전에 Commit할지 사용자에게 묻는다.
2. 받아 올 변경이 무엇인지 먼저 보여준다(`git fetch` 후 새 Commit 목록).
3. 사용자가 확인하면 Pull한다.
4. 새로 들어오거나 바뀐 파일 목록과 내용을 요약한다.
5. 충돌(Conflict)이 나면 그 자리에서 멈춘다. 어느 파일의 어느 부분이 충돌했는지, 양쪽 내용이 각각 무엇인지 보여주고 어느 쪽을 남길지 사용자에게 묻는다.

## 4. 올리기 전에 확인할 것

사용자가 Push를 요청하면 올리기 전에 아래를 보여주고 확인을 받는다.

- 올라갈 레포 주소와 Branch 이름
- 올라갈 저장 지점 목록
- 공유 전 점검이 필요하면 self-check Skill을 먼저 쓰도록 안내한다.
